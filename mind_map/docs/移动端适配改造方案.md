# 移动端适配改造方案 · 思维导图工具

> **状态**：提案（待评审，**未开工**） · 2026-10-25
> **对象**：`思维导图工具.html`（v35 / 8865 行 / 489376 字节，单文件零依赖）
> **目标**：手机浏览器（竖屏 ≈390px 宽）可正常打开、查看、编辑、导出，且不破坏桌面端现有体验
> **原则**：零依赖底线不变；渲染/坐标/双布局算法（C3）一律不动；沿用项目四步验收铁律

---

## 0. 结论先行

- **画布本身已经触屏就绪**（C1：单指平移、双指缩放、长按菜单、coarse 命中区放大都已实现），"手机打不开"的真正原因是**外壳（顶部工具栏 + 大纲栏 + 弹窗 + 浮动件）没有为窄屏折叠**，不是渲染引擎问题。
- 改造量**中等偏大，但属于"响应式外壳重构"，不是"核心逻辑重构"**——C3 双布局共用同一套坐标语义（`x`=左沿、`y`=垂直中心），底层已为"一套布局多端复用"铺好路，渲染主干 `render()` 保持同步，这些**一行都不用动**。
- 工期粗略判断：一个人、聚焦外壳，**2-4 个工作日出能用的 beta**（手机能开、能画、能导）；若要"每个弹窗都手机完美精修"，再 +2-3 天。

## 2. 目标与验收标准

**功能验收（手机竖屏 390×844）**
1. 打开即用：可见紧凑顶栏 + 全屏画布，画布高度 ≥ 屏高 80%。
2. 画布可单指平移、双指缩放、长按出节点菜单、双击编辑、点选高亮。
3. 新增节点有入口（FAB 悬浮「＋」），不依赖物理键盘。
4. 大纲、导出、导入、工作区、历史等面板在窄屏可用、不溢出、可关闭。
5. 12 种导出在手机上能触发下载/复制。

**非目标（范围边界）**
- 不重做渲染/布局算法；不引入任何框架/CDN/字体外链（守住零依赖）。
- 不单独为平板做设计，复用同一套 `≤760px` / `pointer:coarse` 断点。
- 不追求"每个面板像素级完美"放进 beta，精修列为后续阶段。

**验收四步（沿用项目铁律）**：jsdom 专项测试 + 反证（临时还原坏行为确认测试变红）+ 全量回归 + **真 Chrome（390×844）复核**，四步全过才算完成。

## 5. 实施顺序（分阶段，每阶段可独立验收）

- **Phase 1 · 移动导航骨架**：B1 + B2 + B3 + C1 + A1。先让手机"能开、画布全屏"，抽屉能开能关。
- **Phase 2 · 外壳收口**：A2（大纲全屏）+ A3（弹窗窄屏）+ A4（浮动件）。画布之外都规整。
- **Phase 3 · 移动专属交互**：C2（FAB 新增）+ C3（软键盘视口）+ C4（#ctx 靠边）。补齐手机上没有键盘的缺口。
- **Phase 4 · 精修 + 四步验收**：逐面板窄屏精修 + 真 Chrome 390×844 复核 + jsdom专项/反证/全量回归全套跑通。

每阶段结束都走一遍四步验收（专项测试 + 反证 + 全量回归 + 真 Chrome），不累积到下阶段。

## 6. 风险与回退

1. **守住 header 不撑高**：`syncHeader()`（4957）读的是 header 真实高度。抽屉必须是 `position:fixed` overlay，**不参与 header 高度计算**，否则回退到"header 巨高、画布消失"的现状。这是头号风险，专项测试必须锁死"抽屉打开时 `body.mnav` 存在且 header 高度不变"。
2. **抽屉复用原 DOM**：把现有 `btn-group` 包进 `<nav>` 即可，**所有 select 的 change 监听、按钮事件全部保留**，无需重绑；只改容器，不改控件。
3. **不动 C3 / render / layout**：双布局坐标语义共用，这是铁约束。任何涉及 `layoutTree`/`edgeGeom`/`render()` 的改动都不在本方案内。
4. **零依赖底线**：所有样式用原生 CSS media query，不引任何库；FAB/抽屉用原生 DOM API。

## 7. 测试方案（四步，含移动视口）

- **jsdom 专项**（`_test/mobile.js`）：纯 DOM 状态断言，见 3.2。
- **反证**（`_test/_falsifyMobile.py`）：临时把关键改动还原成坏行为（如 ☰ 不切 class、抽屉 CSS 规则被删、FAB 不调 addChild），确认专项测试对应用例变红；结束 sha1 核对还原原件，0 假绿、0 崩溃。
- **全量回归**（`python _test/runall.py`）：36 套 2719 条 + 新增套件，0 失败。
- **真 Chrome 复核**（`_test/_chrome_mobile.py`）：用 `--window-size=390,844`（CSS 视口宽 390 ≤760，自动触发 `≤760px` 断点）；探针验证 `navdrawer` 滑入 transform、`#outline` 宽度、`fab-add` 点击后节点数 +1、`#ctx` 不溢出右缘。

## 8. 不做的事（范围边界，防范围蔓延）

- 不重做渲染/布局/导出引擎。
- 不引入任何外部依赖（框架 / CDN / 字体）。
- 不单独为平板设计（复用 `≤760px` + `pointer:coarse`）。
- 不在 beta 阶段追求"每个弹窗像素级完美"——精修列为 Phase 4 及以后。
- 不改动桌面端默认观感：所有移动样式都收在 media query / `pointer:coarse` 内，鼠标用户看到的界面一个像素不变（与现有 C1 思路一致）。
