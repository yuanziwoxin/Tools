## 1. 现状取证（真 Chrome，中文 1500×1000）

| 指标 | 实测 | 专业参考值 | 判断 |
| --- | --- | --- | --- |
| 顶栏高度 | 73px（两行） | 单行命令栏 44–56px | 吃掉画布 |
| 常驻控件 | 35 按钮 + 9 下拉 = **44 个** | 一屏常驻 7±2 个高频项 | 严重超量 |
| 字号 | 31 个按钮 **11.5px**，4 个 13px | 桌面控件 ≥13px，密集工具 ≥12px | 偏小、难扫读 |
| 最小命中区 | **416px²**（约 22×19）、最小高度 22px | Fitts：桌面 ≥ 28×28，触控 ≥ 44×44 | 易误点 |
| 禁用态 | 9 个按钮常驻灰掉 | 禁用项应收起或保持占位一致 | 视觉噪声 |

| 视口 | 顶栏高 | 两行实际宽 | ⋯ 收拢组数 |
| --- | --- | --- | --- |
| 1920 | 73 | `[1374, 1330]` | 0 |
| 1500 | 73 | `[1294, 1260]` | 0 |
| **1280** | 73 | `[1029, 840]` | **3** |
| 1100 | 73 | `[677, 838]` | 4 |

也就是说：v60 只在 ≥1500 宽的中文环境下成立。常见的 1280 / 1366 笔记本宽度下，**一半功能被塞进「⋯」、两行长度重新拉开**，用户批评的"第一行留空、第二行塞不下"以另一种形式复现了。

## 2. 专业 UX 诊断：六个病灶

1. **信息架构混淆（根因）**：把"命令"（新建、导出、撤销、删除）和"属性设置"（字体 / 字号 / 粗细 / 宽度 / 主题 / 背景 / 配色，共 7 个 `select`）放在**同一层级、同一条带**里。命令是高频、要秒点、要能形成肌肉记忆；设置是低频、需要标签和当前值、适合成对展示。混排导致两者都难用：命令被淹没，设置挤成 70px 宽的小下拉。
2. **渐进披露缺失**：44 个控件全部常驻，违反 Hick 定律（选择时间与选项数成对数增长）。用户每次操作都要在两条文字带里重新扫读，而不是"看一眼就知道去哪"。
3. **视觉层级缺失**：除「导入文档」外，几乎所有按钮共用同一套 11.5px / 浅底 / 细边样式，无 primary / secondary / tertiary 分级，也没有分组标题。危险操作（清空画布、删节点）与"适应窗口"同权重。
4. **Affordance 与命中面积不足**：22px 高的控件、11.5px 字、极窄的下拉箭头，既是视觉问题也是可用性问题；hover 区域不可见，用户不知道哪里能点。
5. **禁用态噪声**：未选中节点时第一行后半段整片灰字，界面看起来像"坏掉的"。禁用控件本应在需要时才出现（见方案 C），或至少保持稳定的占位与对比度。
6. **响应式策略本末倒置**：v60 用的是"连续压缩 + 优先级溢出（Priority+）"，但**没有重排信息架构**。宽度一降就靠 `data-tight` 抠 1–2px、再整组搬进「⋯」，结果是中等宽度下左半屏空白 + 一半功能藏在二级菜单，且行的视觉重量随宽度随机跳变。真正该做的是**按断点换结构**，而不是把桌面两行硬塞进任何宽度。

设计原则（后文三方案共同遵守）：

- **Fitts**：主操作命中区 ≥ 32×32，图标按钮 ≥ 36×36，触控 ≥ 44×44。
- **Hick / 渐进披露**：常驻只放高频，其余按语义分组进一个入口；并提供 ⌘K 命令面板做可发现性兜底。
- **一致性 + 可预测性**：按钮位置不随宽度随机跳变；同一断点内位置稳定，跨断点用明确的形态切换（图标+文字 → 仅图标 → 菜单）。
- **上下文相关**：工具跟着当前任务走，而不是一次全摊开。
- **可访问性**：所有图标按钮带 `aria-label` / `title`；菜单支持 Esc、点击外部关闭、`aria-expanded`。

## 3. 三个推荐方案

### 方案 A（推荐）· Priority+ 单行命令栏 + 设置抽屉 + ⌘K

**一句话**：顶栏压到 **1 行 52px**，只放 6–8 个高频命令（真按钮、图标+文字），所有设置搬进右侧 320px「设置」抽屉，低频命令进「⋯」并按语义分组；用 ⌘K 命令面板兜住全部 44 个功能的可发现性。

**结构**

```
[◆ 思维导图工具  未命名导图]  [+ 新建][⤴ 导入][⤓ 导出] │ [↶][↷] [⌕ 搜索] ⋯  [⚙ 外观] [EN]
                               ↑ 常驻高频命令（位置固定）        ↑ 溢出   ↑ 设置抽屉
```

- 抽屉分三区：**文字**（字体 / 字号 / 粗细 / 宽度）、**外观**（主题 / 背景 / 配色 + 实时缩略预览）、**视图**（层级 / 布局 / 显示选项）。带标签、当前值和预览，不再是 70px 小下拉。
- 「⋯」菜单按 文件 / 数据 / 面板 / 编辑 / 视图 分组，每项含图标、名称、快捷键。

**断点策略**

| 断点 | 宽度 | 形态 |
| --- | --- | --- |
| XL | ≥1400 | 8 个「图标+文字」主命令 + 文档名 |
| L | 1200–1400 | 6 个主命令 + ⋯ |
| M | 1024–1200 | 8 个**仅图标**（tooltip 给名称）+ ⋯ |
| S | 760–1024 | 5 个仅图标 + ⋯，文档名隐藏 |
| XS | <760 | ☰ 标题 + 搜索 / 添加两个图标；抽屉式菜单 + 底部 FAB |

**为什么推荐**：直接解决全部六个病灶；画布净增 21px 以上；一级命令数量稳定，肌肉记忆不被破坏；设置从此有空间写得清楚；⌘K 让"藏起来的功能"依然可发现。断点切换是**形态变化**而非"逐像素抠间距"，中等宽度不会再出现半屏空白。

**代价 / 风险**：设置从"一眼可见"变成"一次点击"；需要新建抽屉与命令面板两处 UI。低频用户可能不知道 ⌘K，需在「⋯」里放一条"搜索全部命令 ⌘K"。

**工作量**：中（约 1 个大版本）。新增设置抽屉 + 命令面板 + 词条；顶栏 DOM 精简；`hdrBalance()` 可简化为按断点的常量表，反而**删掉** v60.1 那套幂等重算。

### 方案 B · 语义标签栏（轻量 Ribbon）

**一句话**：保留两行但**重构语义**：第一行是 4 个标签（开始 / 插入 / 视图 / 外观），第二行**同一时刻只显示当前一组**，用「图标在上、文字在下」的大按钮，组内带分区标题。

**结构**

```
[◆ 思维导图工具]   [开始][插入][视图][外观]                    [↶][↷]  [EN]
 子节点   同级   编辑   删除  │  展开  折叠  层级  │  撤销  重做   ...
  ✚       ＝     ✎     ⌫        ▣    ▤    ①        ↶     ↷
 剪贴板 / 编辑                结构                    历史
```

- 每组只有 8–12 个大按钮，任何 ≥760 宽度都装得下，**零横滚、零溢出菜单**；右端留白自然一致。
- 设置类控件在「外观」页里变成带标签的整齐网格卡片，不再是挤在命令里的小 `select`。

**断点策略**

| 断点 | 形态 |
| --- | --- |
| ≥1280 | 大按钮（图标 20 + 文字 11，40px 高）+ 组名 |
| 1024–1280 | 图标 + 短文字横排，32px 高 |
| 760–1024 | 仅图标 36×36 + tooltip，组名隐藏，仍一行 |
| <760 | 第二行变横向可切分组 chips + 底部抽屉；大按钮 44×44 |

**优点**：语义最清晰，命中面积最大，符合 Office / Figma 用户的心智模型；不用命令面板也能发现全部功能；两行长度天然恒定，永远不会"一空一挤"。

**代价**：切换标签多一次点击；顶栏仍约 88px，画布增益不如 A；标签切换时第二行内容整体变化，位置记忆弱于 A（可用"上次标签"记忆缓解）。

**工作量**：中偏大（标签状态机、4 组内容重排、大按钮样式、窄屏 chips）。

### 方案 C · 上下文浮动工具坞 + 极简顶栏

**一句话**：顶栏只留 **1 行 48px**（品牌 + 3 个文件命令 + 搜索 / 设置 / 语言），工具按**当前选中对象**出现在画布上的可拖动 dock 里：没选中 → 添加 / 模板 / 缩放 / 外观；选中节点 → 子节点 / 同级 / 编辑 / 文字样式 / 删除；选中联系线 → 线型 / 说明 / 删除。

**结构**

```
[◆ 思维导图工具  未命名导图]        [新建][打开][导出]      [⌕ ⌘K][⚙][EN]
┌────────────────────────────┐
│ ⣿ 节点工具   [＋][＝][✎][Aa][⌫] │ ← 可拖动 / 可吸附 / 可收起
└────────────────────────────┘
        ◉ 中心主题 ─── ○ 分支 A
```

- dock 位置固定（默认左上）、**只换内容不换位置**，避免上下文切换造成的位置跳变；可拖动、可吸附左上 / 右上 / 底部、可收成一个小圆钮；状态记进偏好。
- 沉浸 / 全屏时 dock 淡出，指针靠近边缘再显。
- 设置仍用右侧抽屉（与 A 共用）。

**断点策略**

| 断点 | 形态 |
| --- | --- |
| ≥1280 | 左上横排 dock，图标 + 文字 |
| 1024–1280 | 竖排 dock，图标 + 短文字 |
| 760–1024 | 竖排仅图标 40×40 |
| <760 | dock 变底部固定工具条（44px 高）+ FAB，顶栏只留标题与 ☰ |

**优点**：认知负荷最低（当下只看到用得上的 4–6 个）；画布利用最高；触控目标最大；天然消除"禁用态一片灰"——未选中时根本不显示编辑类按钮。

**代价 / 风险**：浮动层遮挡画布（需"只换内容不换位置 + 可吸附 + 一键收起"三条规则兜住）；上下文自动切换若动画太跳会干扰，需要 120ms 内的淡入且保持 dock 矩形不动；新手可能找不到工具，必须配 ⌘K 与首次引导。

**工作量**：大（上下文状态机、dock 拖动与吸附、偏好持久化、移动端底部条）。

## 5. 落地注意（无论选哪个）

- **数据层零改动**：`localStorage` 键 `mindmap-studio-v1` 不变；布局 / 语言 / dock 位置都是偏好，不进 `serialize()`、不压撤销栈，仍走 `savePrefs()`。
- **i18n**：中文原文即 key，新增词条（设置、开始 / 插入 / 视图 / 外观、搜索全部命令、节点工具…）由 `_test/_i18n_build.py` 注入 EN；`I18N_SKIP` 里不放用户内容。
- **顶栏高度**：`syncHeader()` 里 `stage.style.top` 必须跟着新高度走；浮层与 `#frames` 坐标不受影响。
- **第 17 张浮层约束**：抽屉 / 命令面板若做成 `.overlay`，要同步"加浮层六处"与浮层计数；建议做成**非模态侧滑面板**，避开该约束。
- **验收四步**：jsdom 专项 + 反证（拆坏必须变红，反证期间不改产品）+ 全量 `runall.py` + 真 Chrome 多视口探针（标题一行、零横滚、命中面积、断点切换、Esc / 点外关闭）。新断言必须配反证。
- **不清空用户工作区**：只重构顶栏 DOM，节点数据、页签、撤销栈、图片 IndexedDB 全部不动。

## 6. 原型说明

打开 `docs/toolbar-prototypes.html`：

- 顶部可切换 **A / B / C / 现状 v60 对照**；
- 宽度预设 `1920 / 1500 / 1280 / 1024 / 900 / 760 / 390` 加连续滑块，所有方案**真实按断点变形**；
- 中 / EN 切换，验证英文长标签不挤爆；
- 按钮可点（toast）、「⋯」菜单 / 设置抽屉 / ⌘K 命令面板 / Ribbon 标签 / dock 拖动与收起 / 节点选中切换上下文都是**真交互**；
- 每个方案下方附设计原理、断点表、代价与工作量，末尾附对比矩阵。

原型是独立静态页面，**不依赖也不修改产品 `mind_map.html`**。

**直达参数**：`?plan=A|B|C|V&w=1280&lang=en&tab=look`，评审或截图时可直接打开指定方案 / 宽度 / 语言 / Ribbon 标签。

**原型自身验收**（2026-11-08）：

- `node --check` 抽取内联脚本：语法通过；
- `_test/_artifacts/verify_toolbar_proto.js`（jsdom 端到端）：**63 条 / 0 失败**，覆盖四方案切换、五档断点、中英切换、⋯ 菜单与 Esc、设置抽屉、⌘K 命令面板与输入过滤、Ribbon 标签切换、dock 收起 / 展开 / 底部条、节点选中切换上下文、重置状态、全程零 JS 异常；
- 真 Chrome `--headless=new --screenshot` 复核 A@1500 / B@1500 / C@1280 / V@1280 四张渲染图，修正了三处观感细节：A/C 命令区改为紧跟品牌（不再中间留空档）、C 的上下文提示条挪到右上角避免擦碰 dock、页面加宽使 1500 宽原型接近 1:1 显示。

期间修掉一个真实语法错误（`RATIONALE.V.work` 少一个右括号，`node --check` 抓到）与两处测试桩问题（键盘事件派发到 window 而监听在 document，已改监听 window；中文界面下命令面板显示「导出」而非 export，断言已按真实显示修正），并给两条 Esc 断言补了「关闭前确实打开」的前置校验，避免假绿。
