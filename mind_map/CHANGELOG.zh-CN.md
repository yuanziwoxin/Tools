## v65 · 2026-11-09（补齐 XMind 联系线端点 · 外框统一 · 选中外框可编辑）

用户三件事：① 原有 XMind 文件里「组合框↔概要、组合框↔组合框、概要↔节点」的联系导入后丢失，要求把**其他也丢的联系线**一并查清；② 外框和组合框本质是一个东西，统一叫**外框**、只保留一个功能点；③ 选中外框后要能删除、编辑、调样式。并且「不要影响其他原有功能，必须经过严格测试校验，测试通过才算完成」。

### 取证：先穷举端点形态，再谈修

新建 `_test/_artifacts/_diag_v65_links.js`，把 `sheet.relationships` 的 `end1Id/end2Id` 穷举成 12 种形态：节点↔节点、外框↔外框（单点 / 多点）、外框↔概要、概要↔节点、`summaries[].id` 当端点、根 / detached / 未被任何 summary 引用的 `children.summary` 主题、悬空端点、数字 id、老版 `content.xml` 的 `<boundary id>`。**修复前 12 条只保住 5 条**。

根因（沿用 v64 从本机 XMind `app.asar` 抽出的 `/renderer/3112.js`）：官方生成器写的是 `e.source.id / e.target.id`，而导入器的 `h()` 明确接受 `type==='topic' || type==='boundary'` —— 也就是说 **`boundary.id` 本身就能当联系端点**。v64 的 `xmindJsonTopic()` 只把主题 id 放进 `ctx.byId`，`boundary.id`、`summaries[].id`、概要主题自己的 id、以及没有被引用的概要主题都没登记；`xmSheetLinks()` 查不到端点就把整条联系跳过，节点本身也一起丢。

### 修复：端点表与端点类型保真

- `xmCtx()` 新增 `ctx.epById`（端点 id → `{k,node}` 延迟解析或 `{k,id}` 直给），新增 `xmEp(ctx, rawId)` 统一解析两端；`xmSheetLinks()` 改走它。端点类型**保真**为 `node / bd / sum / grp`，不再全部退化成 `node`。
- `xmindJsonTopic()` 登记主题 id、`summaries[].id`、概要主题 id、`boundary.id`；**没有 summary 引用的 `children.summary` 主题当普通子节点收下**，不再整颗丢弃。id 一律 `String()` 后登记，数字 id 也认。
- 老版 `content.xml` 补 `<boundary>` / `<summary>` 的 id 映射，映射到它所在主题（优先第一个子主题）。悬空端点与自环仍然跳过；`xmindJsonTopic(t)` 不带 `ctx` 的 v63 纯文本回读一字未改。
- 修复后诊断脚本 **12 条保住 11 条**，唯一丢弃的是本就该丢的悬空端点。

### 外框统一：一个名字、一个功能点、两种存储

用户可见层只留一套「添加外框 / 编辑外框标题 / 删除外框 / 外框色（5 色 + 清除）」，菜单、联系提示、文字样式按钮与占位文案、读屏 `aria-label` 全部改叫「外框」，旧的 `gbadd/gbedit/gbdel/gbclr/#ctx-gb` 入口全部移除。`frameAdd()` 按单选 / 多选自动分流，`frameOf() / frameEdit() / frameDel() / frameSetColor() / frameColor()` 统一识别两种框。

**内部仍保留 `bd`（单节点外框）与 `root.groups + gb`（多节点外框）两种存储**：旧存档、XMind 导入、联系端点、文字样式、四种导出几何全都不用迁移，这是「不影响原有功能」的关键取舍。旧偏好 `fsKind='gb'` 靠两个 `hidden` 的 `<option>` 占位继续兼容，`FS_KINDS` 仍接受 `gb`。

### 选中外框后能删、能改、能调样式

- 点框标题 = 选中外框：给 `.bdf/.gbf` 加 `.sel`，用 `box-shadow` 画选中环（**不改 `border-width`、不动几何**），框体仍是 `pointer-events:none`；点别处 `selectNode()` 自动撤环。
- **直接右键框标题**就弹出统一外框菜单，不必再绕回节点上右键。
- 框被选中时 `F2` 编辑框标题、`Delete / Backspace` 删除外框 —— 否则按 Delete 会把整颗节点连同子树一起删掉，这是本次补掉的一个真实误操作。没选中外框时 Delete 仍按老行为删节点。
- 改色落到 `bd.c` 或 `root.groups[].c`，色板高亮当前档；删除外框保留全部节点，操作都带可读撤销名。

## v64 · 2026-11-08（XMind 导入 / 导出补齐外框、概要、联系、插图）

用户反馈：XMind 的**导入与导出**都带不动外框、概要、联系和插图。盘点后：导出侧概要（v63 已修）、外框 / 分组框、联系本来就有原生字段，但都缺 XMind 的 `class` 标记，**插图完全没写**；导入侧 `xmindJsonTopic()` 只读标题 / 备注 / 完成 / 链接 / 子节点，四类**一个都不认** —— 所以「导出再导入」必然丢光。

### 取证：继续拆本机 XMind app.asar

沿用 v63 的路子，从 `resources/app.asar` 抽出 `/renderer/3112.js`，把 content.json 导入器的字段链逐条读出来（这次不靠猜）：

| 附件 | XMind 官方字段 |
| --- | --- |
| 外框 / 分组框 | `topic.boundaries:[{id, class:"boundary", title, range:"(a,b)"}]` —— 单点 `(i,i)` 圈一个主题子树，多点圈连续子主题 |
| 概要 | `topic.summaries:[{id, class:"summary", range, topicId}]` + 概要主题住 `topic.children.summary` |
| 联系 | `sheet.relationships:[{id, class:"relationship", end1Id, end2Id, title}]` —— 两端 id 必须能映射到已注册主题 |
| 插图 | `topic.image:{src:"xap:resources/<n>.<ext>", width:number, height:number}` |
| 资源 | 图片字节进 zip 的 `resources/`，且**必须**在 `manifest.json` 的 `file-entries` 里登记 —— 26.x 加载器对未登记条目按 `{path,encrypted:true}` 兜底，会把图片当密文解不开 |

官方生成器的 manifest 写法正是本轮采用的 `{"file-entries":{"resources/x.png":{}}}`（取证 `renderer/6192.js` 的 `toJSON()`）。

### 导出侧

- 四类字段补齐 `class`；`xmindParts()` 不再偷用全局 `root`，改读传入的 `tree.groups`。
- **插图**：新增 `xmDataUrlBytes()` / `xmBytesDataUrl()` 二进制桥，把原图（拿不到就退回轻量副本）写成 `resources/xmN.<ext>`，`topic.image` 只留 `xap:` 引用；`manifest['file-entries']` 登记每一份资源；同一张图被多个节点引用只打包一份。`exportXmind()` 先 `await imgPrepareExport()` 备齐 IndexedDB 里的原图，`xmindParts()` 本身仍保持同步。
- **联系的弧度不丢**：XMind 的 relationship 没有 bend / shift 这一维，拖好的弧线放进 `sheet.extensions` 的 `mindmap-studio` 命名空间（官方扩展字段），本工具再导入时按端点匹配复原；没拖过的联系不写扩展。

### 导入侧

- `xmindJsonTopic(t, ctx)` 双模式：**不带 ctx 仍是 v63 的纯文本回读**（既有断言与外部调用一字不改）；带 ctx 时把 `children.attached` 收为真实子主题、`children.summary` + `summaries` 还原成 `sum:{a,b}` 概要节点（排真实子节点之后）、`boundaries` 还原成单节点 `bd` 或根上的 `groups` + 成员 `gb`、`image` 还原成节点 `img` 并把原图灌进 `tree.images`（`applyImportedTree` → `imgBootInline`）。`xmSheetLinks()` 把 `relationships` 变成 `links`，只给真正被调用的端点发 `uid`。
- **大图不破净化口径**：`build()` 的 `imgOk` 有 `src` 长度上限，原图太长时先记在不可枚举的 `__xmBig` 上，`readXmindFile()` 用 `Image` + `imgThumbOf()` 异步缩一张轻量副本再建树；解码不了也绝不拖死导入。
- 老版 `content.xml` 也补了主题 id 登记、`<relationship>` 与 `<image>` 的读取；危险 `image.src`、越界 range、找不到 topicId 的概要、悬空端点的联系一律跳过而不是抛错。

## v63 · 2026-11-08（修复「导出的 XMind 文件打不开」：概要主题搬进 children.summary）

用户实锤：导出的 `.xmind` 在 XMind（26.x）里直接报 `Error: Not a JSON array: undefined` 打不开。取证方式是硬核的：直接从用户本机 XMind 安装目录的 `app.asar` 里抽出报错的 `renderer/3112.js`，按报错栈列号逐字解剖导入器源码，拿到了铁证 —— XMind 解析父主题的 `summaries` 时硬性执行 `p(_(g(parent.children).summary).find(t => g(t).id === topicId))`：**概要主题必须住在父主题的 `children.summary` 数组里**。旧导出把概要主题塞在 `children.attached` 里、`children.summary` 缺省 → 图里只要有概要就必崩（没有概要的图反而能开，所以一直没暴露）。

### 修复三件套

- **概要主题搬进 `children.summary`**：真实子主题照旧进 `children.attached`，概要主题住 `children.summary`，父主题用 `summaries:[{range, topicId}]` 指过去 —— 这才是 XMind Zen / 2020+ 的规范模型，XMind 打开后能认出括线的原生语义（顺带修正 range 收口按真实子主题数计算，不再把概要主题算进下标）。
- **`marker` → `markers`**：XMind 读的字段名是 `markers`，旧名导致完成标记（task-done）在导出里被静默丢弃；导入侧同步改成**双认**（新 `markers` / 旧 `marker` 都能读回完成态）。
- **metadata.json 补 `dataStructureVersion: "2"` + `layoutEngineVersion: "4"`**：官方版本判定字段，与实测可被 XMind 26.5 打开的生成器口径一致。

### 验收方式（重点：导入器模拟器）

新专项 `v63.js` 内置一个**逐字复刻 XMind 导入器严格断言链的「导入器模拟器」**（`g(children).summary` → `_(...)` → `find(topicId)`），直接跑在导出产物上 —— 断言名字就是用户看到的报错。真 Chrome 探针 `_chrome_v63.py` 再跑**完整导出链**（`exportXmind` → 真打包 ZIP → python 解包 → 结构逐层校验 + 模拟器），做到「真打包产物与 XMind 解析器逐字兼容」。

**验收**：`v63.js` **22 条 / 0 失败**；`_falsify_v63.py` **4 颗全咬**（①概要搬回 attached ②markers 退回旧名 ③拆版本字段 ④导入侧拆双认）；真 Chrome `_chrome_v63.py` **14 条 / 0 失败**（真打包产物）；`_falsify_chrome_v63.py` **1 颗咬住**（真打包产物上老病复发必红）；全量 **56 套 / 4278 条 / 0 失败**；反证后复跑 14/0、sha1 `6b272bbd24b9` 一致。产品 **14911 行 / 858570 字节（约 838 KB）**；反证 **60 份**、真 Chrome 探针 **42 组**。测试侧同期修掉三颗假绿根因：断言名带「：」被反证解析器截断（第二次踩）、反证拆坏后新断言取值未兜底崩套件、topicId 收集池没有只认规范位置。

## v61 · 2026-11-08（修复刷新后插图节点压框线：启动几何稳定化复核）

用户反馈：刷新页面时**有时**插图节点会和外框 / 分组框虚线重合，有时又正常；同一份导图反复刷新结果会变。这是典型时序竞态——但要先取证，不猜。

### 取证与根因

真 Chrome 三类排查排除了「图片解码」假说：`.thumb` 固定 96px 高、`img{max-width:100%}`，图片解码前后根本不改变节点尺寸；启动两次 `render()`（含 `applyLang()` 那次）的框矩形逐像素一致；穷举 96 组几何（节点宽度 × 横纵布局 × 插图位置 × 框型 × 缩放）稳态零覆盖。

真正的根因：`render()` 在 `<script>` 同步执行期间量 `offsetWidth/offsetHeight`，据此算 `n.w/n.h → contentRect → 框几何`。首帧若被任何未落地资源干扰（字体 / 顶栏 / 滚动条 / 样式），卡片就按错的尺寸量，框按错的几何画，**且永远不自愈**——直到用户手动触发一次 `render()`。「有时重合、有时正常」正是首帧测量是否偏了。

测试先行：`_chrome_v61.py` 用 `?firstframe=1` 在首帧注入 `.node{width:120px!important}`、`load` 后移除，精确复现「首帧量窄、最终变宽」。修复前量到 **279 个框沿采样点被插图卡片盖住，4 次刷新都不自愈**。

### 修复：幂等的几何稳定化复核

- `render()` 里记录每张卡片的实测尺寸（`n.__sw/n.__sh`）；新增 `geomStableRecheck()`：DOM 实测尺寸与记录不一致时 `renderSoon()` 补一次渲染，一致就零动作。
- 挂四个触发点：缩略图 `load` / `error`（`{once:true}`，图片只在解码完成那一刻可能改变尺寸）、`window.load`（字体 / 顶栏 / 滚动条全部落地）、启动后 400ms 兜底复核。全部幂等：尺寸一致时不重渲、不动撤销栈、不写存档。
- 循环安全：复核只补**一次**渲染，重渲后重新记录尺寸；不存在「复核 → 重渲 → 再复核」死循环。

## v53 · 2026-11-05（联系线不再打结 · 悬停预览也能按住在拖）

用户报的两件事：「现在联系线会有打结」「悬停预览图时，鼠标放在预览图按左键移动，预览大图和后面的画布都不动」。

### 联系线打结

**根因**（量出来的，不是猜的）：`linkCurve()` 把两个控制点沿弦方向拉开的距离写成
`lead = 0.3×弦长 + 0.55×|bend|`。三次贝塞尔的折线 `P0 → M1 → M2 → P3` 必须**顺序前进**，
两个控制点在弦上的间距是 `弦长 − 2×lead`；v51 放开 `bend` 到 ±900 之后，拖过 150 左右
这个间距就变成负数 —— 折线先回折、曲线再绕成一个圈。

用 320 组「弦长 × bend × shift」采样统计：**改前 242 组自交，改后 0 组**。逐档扫比例时，
lead 到 1.0 倍弦长仍不自交、1.2 倍必然自交，所以取 0.42 是留了两倍余量。

**改法**：`lead` 只按弦长取固定比例 —— `clamp(chord × 0.3, 6, chord × 0.42)`，
上限死死压在弦长的一半以下。大弧度时曲线变成一条**细长的绕行弧**：窄，但绝不回头。
`bend` / `shift` 仍然是 ±900 的硬夹，避让能力一点没缩水（bend=900 时弧顶离弦中点 675px）。

### 悬停预览按住拖动

预览层以前一个指针监听都没有 —— 按住它什么都不会发生（v52 只做了大图浮层）。

现在：按住预览图（或它的说明条）拖动，**预览框跟手走，背后的画布同时平移**，位移方向
和距离与手一致；不到 3px 仍按「单击」处理，照旧打开大图；拖动中指针短暂离开预览框
不会把它收起来；右键不参与；视图变化不入撤销栈、不标脏。

### 过程中追出来的一处真实缺陷

第一版给预览框记了一份「相对锚点的偏移」，本意是让滚轮缩放后框停在原处。真 Chrome 一量
——放大后框整整跳了 170px。原因是拖动时画布和缩略图一起移动，框相对缩略图其实没变；
再叠一份偏移就是**双重计数**。改成「定位只按锚点算」后归零。这条也进了反证。

**顺手修掉的一处**：拖动位移原来用「两次 `worldPt()` 相减」，而它依赖画布 rect / `tx` / `ty` / `scale` 四个量 —— 拖动中途只要有一个变了（滚动条出现、浮层收起、滚轮缩放），位移就会凭空多出或吃掉一整段。现在按下时把基准钉住（`c0` + 起始缩放），中途怎么变都按那一下算。

## v50 · 2026-11-04（插入图片保存原图：轻量副本 + IndexedDB 双份 + 导出内联）

**改成双份，各管各的**：

- 节点上只留**轻量副本**（长边 320px / 96 KB 上限）给布局与缩略图用，另加 `oid` / `ow` / `oh` / `os` 四个短字段记原图身份与尺寸；
- **原图逐字保真**存进 `imgOrigMem` 内存表 + 固定库名 `IMG_DB='mindmap-studio-orig-v1'` 的 IndexedDB —— 不重编码、不降质量、GIF 也不会被 canvas 拍成首帧 PNG；
- 「原图已按原样保存，放大和导出都用它」这条提示只在真的落库成功后出现；文档里没有大字节，撤销栈 / 页签槽 / 自动备份都不再被图撑大；
- **小图早退**：尺寸 ≤ 320px、体积 ≤ 96 KB、MIME 合法时，轻量副本直接就是原图本身，零重编码；
- `imgOk()` 仍是唯一收口。旧版（v47–v49）没有 `oid` 的图照常读；非法 `oid` 按净化口径丢字段、图本身照收。

**显示与导出都拿原图**：`render()` 保持同步（`imgBestSync()` 先用当前拿得到的那一份顶上），异步只发生在插入落盘、浮层换图、导出边界三个地方；`openImgView()` / `imgHoverShow()` 随后用 `imgBest()` 把画面换成原图，`ivScaleTo()` 的 **100% 按原图像素**算，不再误用副本尺寸；`imgXSrc()` 让 PNG / SVG 解码的也是原图。

**单文件流转一点不丢，五条边界**：

1. 独立网页 `.html` 把原图内联进 `IMG_DATA`；导图 `.json` / 工作区 `.json` 加同级 `images` 表；
2. 导入（`.json` / 工作区）与导出件启动都走 `imgBootInline()`，把原图灌回接收端内存并落进**接收端自己的** IndexedDB；恶意内联只收 MIME 与 `oid` 都合法的那几张；
3. 导出件**只换 `STORE_KEY`、绝不换 `IMG_DB`**，并保留 `/*<<IMG_DATA_END>>*/` 标记 —— 所以导出件可以再导出，图不丢、也不会把旧孤图一直带下去；
4. 导出件会清掉 `#iv-img` / `#ih-img` 的运行时 `src` 与 `#iv-info` / `#ih-cap` 的说明行。否则当前浮层那份原图会被再内联一遍（文件白胖一倍），上一位用户的运行时文字也会跟着出门；
5. **所有导出先同步取 `doc = serialize(root)`，再 `await` 原图表**。本轮真踩过这个坑：快照放到 `await` 之后，「备份 .json 并继续」会在等待空隙把 `root` 换成空白画布，结果导出一份空图（`run.js` 当场变红）。`exportJson()` / `exportHtml()` / `bkWriteNow()` 三处同改，静态守卫锁住时序。

`imgGc()` 在启动 8 秒后保守回收：只删没有任何 localStorage 槽 / 撤销 / 重做 / 当前画布 / 本次会话引用的孤图，**撤销还能恢复的原图绝不会被提前删掉**。没有 IndexedDB 的环境自动降级（内存里有原图就照常用，只是不跨刷新），功能不残废。

## v48 · 2026-11-04（框与框不再交叉：一个节点占的那一块，就含它自己那层框）

**解法只有一句话**：一个节点在布局里占的那一块，永远包含它自己那层框；画框时用的是「内容盒」，也永远包含子树里的框。

## v43 · 2026-11-02（分组框：把选中的几个节点圈成一组）

**外框框的是「一条分支的整棵子树」，分组框框的是「你选中的那几个」** —— 可以跨分支，也可以只是同一层的几个兄弟。
多选 2 个以上节点 → 右键**为选中节点加分组框**，它们外面就多了一圈虚线（圆角 18、标题贴在框内顶部居中）。

它和另外两个「框」分工很清楚：**外框**的范围由那个节点自己决定；**概要**的范围是一个连续区间、还会长出一个概要主题；
**分组框**的范围由你的多选决定，不长节点、不改结构。

**存法与概要完全不同，这是刻意的**：组定义挂在根节点上 `groups:[{id,t,c}]`，成员节点只挂一个 `gb:<id>`。
这样复制 / 粘贴子树时，`gb` 指向的组不存在，收口那一步直接把它丢掉 —— 「粘出来的不带组」不需要额外写一行代码。

**最关键的一条：分组框不参与布局。** 它是背景层，画在连线与节点之下，加框前后整张图的坐标一个像素都不变
（真 Chrome 与反证都在守这一条：给 layout 加一行让位代码，断言立刻变红）。
让位要重排整棵树，跨分支的组又没法局部让位；线在背后被节点盖住，视觉上已经足够「框住」。

其他几条边界：

- 一个节点只属于一个组；**删到只剩一个成员，组自动解散**（一个节点的「一组」没有意义）；
- **已经是别的组的成员，不参与新建组** —— 否则一次误操作就把原来的组标题和颜色冲掉；
- 组成员折叠 / 被层级截断 / 被「只看命中」挡掉时，框自动缩到还看得见的部分；成员全被挡住就暂不画；
- 框体穿透（`pointer-events:none`），只有那条标题可点。

**导出**：PNG / SVG / PDF 画（含标题），JSON 留 `groups` 与 `gb`，文本类（MD / Word / Excel / OPML / PPT 大纲）刻意不带。
XMind 顺手补上了原生 `<boundary>` —— 分组框在「成员正好是同一父节点下一段连续兄弟」时转 boundary，
**单节点外框也一起接上了**（range 退化成单点，圈住那条分支和它的子树），至此 P1.5 的 XMind 部分补齐。

验收：jsdom `groupframe.js` **85 条**、反证 **7 轮全咬**、全量 **41 套 3120 条 0 失败**、真 Chrome **38 条**。

## v42 · 2026-11-02（概要：一条括线把几个兄弟总结成一句话）

**外框框的是「一条分支的整棵子树」，概要总结的是「几个兄弟」。** 选中同一父节点下 2 个以上节点 →

**概要主题是一个真正的节点**，不是一行贴上去的标签。它就住在 `children` 里，只多一个标记：

```js

```

这一个决定白拿了选中、双击编辑、上色、折叠、复制 / 克隆 / 粘贴、撤销、以及全部导出遍历 ——

**区间是索引，不是引用** —— 本工具的节点没有 id。所以它得扛住改动：在区间**内**插入 → 变长；

## v41 · 2026-11-01（外框：用虚线框把一条分支「圈起来」）

**外框是挂在节点上的装饰，本身不是节点**。加在哪条分支上，就包住那条分支和它**看得见**的后代。
右键节点可取**添加外框 / 编辑外框标题 / 删除外框**，「外框色」后面那五颗色块定颜色（点一颗同时也会把框加上）。
双击框上的标题即可行内改字：回车保存、Esc 还原。

因为它挂在节点上，其余全部白拿：复制、克隆、粘贴、上下移、删除，框都跟着一起走；删掉节点，框也一起没，不会留下悬挂引用。
折叠这一支、用「显示到第 N 层」截断、或只看搜索命中 —— 框自动缩到还看得见的那部分，这不是特判，就是包围盒重新算了一遍。
允许嵌套：子节点可以有自己的框，套在父节点的框里面。

**布局只让位，不动列模型**。带框的分支上下各留 `BD_PAD = 14`，相邻两支**只要有一支带框**，中间再补 14 ——
实测两个框之间 **26px**（GAP_Y 12 + 14）。少了这条，两个虚线框只隔 12px，看着几乎贴在一起（原型实测抓到的）。
`colX[]` / `colW[]` 一行没改：`GAP_X` 是 64，远大于 14，框的右沿伸进列间隙也压不到下一列。
纵向（组织结构图）只在横向让位 —— 它 44px 的行距本来就吃得住 28px，`orgRowY()` 不用动。
这正是外框能低成本落地的原因：**它要的是「空间」，不是「新的一列」**。

**它不吃点击**。`#frames` 在 DOM 里排在 `#edges` 之前，所以框画在连线之下、节点之下；框体 `pointer-events:none`，
只有标题可点（点它等于选中所属节点）。真 Chrome 的 `elementFromPoint` 三条都验了：标题点得到、节点中心仍然命中节点、
框内空白处穿透到画布。

## v34 · 2026-10-19

第十二轮「**N3 节点链接 · URL / 本机路径**」。

资料整理、学习笔记、项目清单里，一个节点常常要指向一份外部材料 —— 一个网页、一份本地 PDF、
一个共享目录。以前只能把地址写进节点名字（又长又丑）或备注（看不见），现在有了专门的 `link` 字段。

### 三件事必须同一套函数判出来

`linkNorm` / `linkKind` / `linkHref` 三个函数是唯一入口，否则会出现「能挂不能开 / 能开不能导出 /
导出的是坏链接」各漏一边：

| 你挂的是 | 点一下 | 导出成 |
| --- | --- | --- |
| `https://…` / `http://…` / 邮件 / 电话 | **新标签页打开** | 真链接（MD / HTML / Word 的 `w:hyperlink`） |
| `D:\资料\x.pdf` / `/Users/a/b.md` / 相对路径 | **复制到剪贴板** | 文本附注（`> 链接：…` / Word 灰字行 / Excel 一列） |
| `javascript:` / `data:` / `file:` 等 | **拒绝并说明原因** | **哪儿都不出现** |

浏览器**不允许**网页直接跳 `file://` 或本地路径 —— 硬跳只会静默失败。所以本机路径走「复制 + 说清原因」，
而不是假装成功。危险协议（能执行脚本的那些）一律不认：导出的独立 HTML 是要发给别人双击打开的，
一个 `javascript:` 链接就是现成的 XSS。

> 判定顺序里藏着一个坑：**盘符必须先于协议判**。否则 `D:\资料\x.pdf` 会被当成一种叫 `D:` 的协议，
> 直接落到「不认」那一档 —— 而本机路径恰恰是这个功能一半的用途（反证里把它改回去，10 条断言当场变红）。
> 同理，协议名刻意**不许带点**，否则 `a.com:8080` 这种「域名 + 端口」也会被误判成协议。

### 冲突：Ctrl+单击仍然是加选

报告里点名的冲突就在这里。B6 的 `Ctrl/⌘+单击` 是「加选 / 减选」，**绝不能抢**。
所以打开链接走两条别的路：

- **点节点右上角那颗链环**（它是唯一可点的角标，其余几颗都是纯展示）；
- **`Alt+单击` 节点**（鼠标 Alt 键在本工具里原本没有别的用途）。

没挂链接的 `Alt+单击` 会**退化成普通单击**，不会变成「点了没反应」。
反证里把 `Alt` 换成 `Ctrl`，4 条断言立刻变红。

键盘入口：`Ctrl+Shift+L` 挂链接（与备注的 `Ctrl+Shift+M` 对称），`Alt+Enter` 打开。

### 角标位置：右上角，与备注角标错开

四个角早就各占一位（左上语义图标 / 右上备注 / 左下截断 / 右下完成），所以链接跟备注**挤在同一个角**，

第九轮「**C3 多布局 · 组织结构图**」。以前只有「左→右」一种方向 —— 汇报关系（谁向谁汇报）用
竖着读才顺，可这工具画出来永远是横的，只能截图后自己脑补。

这一轮加了 **布局** 下拉：**左右**（思维导图，默认）/ **上下**（组织结构图）。

### 动手前先定映射表

| 关注点 | 原来（左→右） | 现在（上→下） | 落点 |
| --- | --- | --- | --- |
| 层间方向 | x = `colX[depth]` | y = 按层累计行高 | `layoutOrg()` |
| 同层排布 | y = tidy 子树 | x = 按子树横向跨度铺开 | `layoutOrg()` |
| 节点定位 | `left = x` / `top = y - h/2` | **不变** | `render()` 一行没动 |
| 连线端点 | 父右中 → 子左中 | 父下中 → 子上中 | `edgeGeom()` 单点 |
| 折叠圆点 | 节点右侧中点 | 节点底部中点 | CSS `body.layout-org` |
| 方向键 | ← 父 / → 子 / ↑↓ 同层 | ↑ 父 / ↓ 子 / ←→ 同层 | 键盘处理单点 |
| 边界 / 适应窗口 / 缩略图 / 框选 | 用 x/y | **不变**（org 的 x 天然从 0 起） | 一行没动 |

关键取舍：**两套布局共用同一份坐标语义（x = 左沿，y = 垂直中心）**。
这样 `render()` 的定位、`bounds()`、`fitWidth()`、`ensureVisible()`、缩略图、框选命中
全都不用改 —— 只改「x/y 怎么算」和「连线从哪条边出去」这两件事。
否则每多一个消费方就要多一处 `if(纵向)`，日后必然漏一处。

### 纵向布局算法

- **行高按这一层最高的节点取**（`orgRowY()`），同层节点才会对齐成一条线；
  节点各自居中会画成波浪线。
- **先量子树跨度、再摆放**（`orgMeasure()` → `place()`）：子节点从左到右按跨度铺开，
  父节点居中在「首尾子节点的中点」上 —— 不是整块跨度的中点，否则一枝独苗也会歪。
- **折叠 / 「显示到第 N 层」挡住的子树一律不参与测量与摆放**，两处都要判（`orgMeasure` + `place`），
  漏一处图就会被看不见的东西撑开。
- 坐标自然满足 `minX = 0 / minY = 0`，所以下游那些「默认左边界是 0」的代码不用动。

### 四种输出共用一份端点函数

原来屏幕、PNG、SVG 导出、PPTX 导出**各写了一遍**「父右中 → 子左中」的贝塞尔：
加一种布局就要改四处，漏一处就是「屏幕上对、导出的图错」。
现在统一成 `edgeGeom(p, c)`，返回两个端点 + 两个控制点，四家都调它。

> 顺带发现 PNG 传给子节点的数据只有 `{x, y}`，纵向端点要用到 `h`，一并补上。

### 顺手删掉的冗余

## v30 · 2026-10-18

第八轮「**C1 触屏 / 平板**」。以前这套工具在平板上几乎是废的：`pointer*` / `touch*` 监听数量是 **0**，

### 两条动手前定的红线

1. **鼠标路径不迁移，只加早退**。`PointerEvent` 会**先于** `mousedown` 触发，两套监听都处理就是
   「按一下动两下」。所以 `pointerdown` 里遇到 `pointerType === 'mouse'` 一律 `return`，
   鼠标继续走原来的 `mousedown / mousemove / mouseup`。
   > 为什么不干脆全迁到 pointer 事件？30 套既有测试全部用 `mousedown` 派发，迁过去等于把
   > 1900 多条断言的语义重写一遍，风险远大于收益。
2. **两套输入共用同一份实现**。把原来 stage 上那三个匿名处理器抽成 `stageDown / stageMove / stageUp`，
   鼠标与手指都调它 —— 否则「鼠标能拖、手指不能」的偏差迟早冒出来。`stageMove` 多一个阈值参数
   （鼠标 3px、手指 10px），因为手指抖动本来就比鼠标大。

### 手势清单

| 手势 | 做法 |
| --- | --- |
| 单指平移 | 与鼠标同一套 `tx/ty`；新的一下按下先把上一轮残留的 `moved` 清掉 |
| 双指缩放 | 记住两指中点底下的**世界坐标**，`tx = (mid.x - r.left) - wx * ns`；松开一根时用剩余那根重新对基准并把平移接回来 |
| 长按出菜单 | 520ms；移动超过阈值或抬手都取消；触发时先 `cancelNodeDrag()`，之后挡掉安卓补发的原生 `contextmenu` |
| 双击改名 | 间隔 < 340ms + 落点 < 30px + 同一个节点；拖动过的节点不算「点击」 |
| 拖节点改挂 | 阈值 10px（鼠标 5px），命中检测仍用 `elementFromPoint` |
| 缩略图挪视口 | 缩略图上单独接 pointer 三件套（它挂在 `body` 上，不在画布手势层里） |

  真 Chrome 探针若撞上这个窗口，读到的就是被改坏的版本 —— 本轮第一次跑就拿到了
  「80 步 / 8.5 MB」（那正是反证里「字节上界 ×100」那一轮）。现在固定成：**反证跑完再复核**。
- **两条断言写错了量（反证揪出来的）**：
  ①「自救不动自己的槽」—— 我原来只断言槽**登记**还在，而自己的槽本来 `closed: false`
  会被第二个条件先拦住（双保险），只拆一处必然假绿 → 改成断言「**存档数据**还在」+ 反证两处同拆；
  ②「删除单条」—— 我原来断言「剩下的时间仍倒序」，而删掉第一条时间照样倒序 → 改成比对**内容标记**。
- **崩溃不算好的反证**：早期有几轮是脚本取值时空指针直接崩掉（看不到是哪条断言在起作用），

#### O5-0. 先给快捷键立一个「唯一数据源」

| 字段 | 含义 |
| --- | --- |

#### O5-1. 冲突审查（报告点名的两个，加全表扫一遍）

#### O6-1. 浮层语义：10 张卡一次补齐

`role="dialog" aria-modal="true" aria-labelledby=<标题 id>` —— 统计 / 备注 / 批量 / 模板库 / 欢迎页 /
导入 / 导出 / 自动备份 / 速查九张用 `dialog`，**确认框用 `alertdialog`**（它要打断用户）。
标题都套了一层带 id 的 `<span>`，`aria-labelledby` 指过去；每张卡里的 **✕ 补上 `role="button"` + `tabindex="0"` + 独立 `aria-label`**。

另外两处：`#ctx` 右键菜单补 `role="menu"`，15 行补 `role="menuitem"`；欢迎页四张大卡片
（原本是纯 `div`，键盘完全够不着）补成 `role="button" tabindex="0"`。

`role=button` 的 `<span>/<div>` 不会自己响应回车和空格，所以加了一条统一委托：
命中就把事件 `preventDefault()` + **`stopPropagation()`** + `click()`。
**`stopPropagation` 是必须的** —— 不然点面板里的 ✕ 时，那个空格会一路冒泡到 window，
撞上画布那套「空格＝折叠展开」，一次按键干两件事（真 Chrome 里验证过）。

#### O6-2. 焦点管理：进得去，出得来，跑不掉

三个动作，全文件只做一遍、所有浮层共用：

1. **进得去**：打开时记下「是谁打开的」，把焦点送进卡片里**最合适的那个控件**。
   选择顺序是「正文里第一个控件（**跳过复选框 / 单选框**）→ 页脚第一个 → 卡片本身」：
   导出面板一进来停在第一个格式按钮而不是「仅导出选中分支」（不然随手一个空格就把范围改了）；
   确认框用 `prefer` 指定停在**「取消」**上（别让误回车把画布清了）。
2. **出得来**：关闭时把焦点**还给那个触发按钮**，不是还给 `body` —— 否则键盘用户会被甩回页面开头，
   接着按 Tab 得从头一个个摸过去。触发者若已不在文档里就安静地不还。
3. **跑不掉**：`Tab` / `Shift+Tab` 在卡片内部循环，不会跑到背后那块被遮住的工具栏上。
   这条放在全局 keydown 的**最前面**（模态的定义性行为，不能被后面任何一条 `return` 抢在前面）。

顺带修掉一个**真实缺口**：老的 `Esc` 链只认了模板库 / 备注 / 批量三个，
**统计、导入、欢迎页、确认框、自动备份按 Esc 是没反应的** —— 一个标了 `aria-modal` 的对话框居然关不掉。
现在统一成「点它自己的 ✕」，走各面板既有的关闭逻辑，焦点归还也就一并带上了。

#### O6-3. 大纲补 tree 语义 + roving tabindex

`#ol-body` 补 `role="tree"`；每一行补 `role="treeitem"` / `aria-level`（与画布同一口径：depth + 1）/
`aria-expanded`（有子节点才写）/ `aria-selected`。

再补上 **roving tabindex**：整棵大纲只留**一个** Tab 站（当前选中那一行，其余 `tabIndex = -1`）——
不这么做的话，几十个节点会把 Tab 键排成一长串，键盘用户得按上百次才能走到别处。
配套的键盘操作：**↑↓ 走行、←/→ 折叠展开、Enter 定位、F2 就地改名**。
方向键在行间走，所以必须 `stopPropagation()`，否则会冒泡到 window 的画布导航，**按一下动两处**。
`←/→` 展开后 `render()` 会重建整棵大纲，新行是新元素，**焦点得自己按 `__olNode` 接回来**，否则焦点就掉了。

#### O6-4. 缩略图：给 canvas 一条键盘替代路径

`<canvas>` 里的图形屏幕阅读器读不出来，鼠标拖拽键盘也够不着。补 `tabindex="0"` + `role="img"` +
描述键盘用法的 `aria-label`，并接上键盘操作：**Home / End 直接跳到第一个 / 最后一个一级分支，
←/→ 在分支之间逐个走**，跳过去的同时选中并把它带进视野（视口 `transform` 真的会变）。

#### O6-5. 顺手抓到一个既有 bug：重复的 id

`bk-close` 这个名字被用了两次 —— 批量文本工具的 ✕ 和自动备份面板的「关闭」按钮。
`getElementById` 只认第一个，于是两处 `onclick` 赋值**全落在批量面板那颗 ✕ 上**：
①批量面板的 ✕ 点了会去关「自动备份」（关不掉自己）；②备份面板的「关闭」压根没绑上。

#### O6-6. 焦点可见

`：focus-visible` 只在键盘导航时画焦点圈（鼠标点击不画）。
**刻意不包含画布节点** —— `#nodes .node` 的 `outline` 已经被搜索高亮（`.hit`）占着，

### 第 28 轮（大图）：O3 渲染节流与可感知性能

#### 0. 先说边界：`render()` 没有变成异步

`render()` 在全文件有 **60 多处**调用点，而且绝大多数是「先 render、再立刻读 `flat` / 节点元素」的
同步依赖 —— 导出、`fitWidth()`、缩略图、大纲、`ensureVisible()` 全都靠它。把它包成 rAF 异步，
这些调用点会全部读到上一帧的结果，属于自找麻烦。

所以这一轮做的是**分流**：`render()` 保持同步，另开一条 `renderSoon()` 给「高频输入」走。

#### 1. `renderSoon()`：同一帧里的多次请求合并成一次

- 真正会一秒触发几十次的只有**搜索框边打边搜**（`findInput` 的 `input`）。现在它走 `renderSoon()`：
  同一帧里的第 2、3、N 次请求直接被并掉，一帧最多渲一次。输入框的值在**回调里**读，
  所以拿到的永远是最后一次输入。
- 反过来，**同步 `render()` 一进门就先 `cancelRenderSoon()`** —— 这一帧既然已经有人真的渲了，
  排队里的那次就没有意义，取消掉免得白渲两遍。
- 关掉搜索条时会 `cancelFindInput()` 撤掉排队中的那次；队列回调里还复查一次「搜索条还开着吗」——
  双保险，避免关了搜索条又自己搜回来。
- `rafCall()` / `cafCall()` 把 rAF 的调用方式收在一处（缩略图的 `mmSchedule()` 也改用它）。

#### 2. `findRun()` 少渲一遍

旧写法是 `findCompute(); render(); if(命中) findGo(1);` —— 而 `findGo()` 内部本来就会
`render()` + 定位 + 刷新计数，**前面那次全量渲染的结果立刻被下一次覆盖**，纯属白渲。
现在：有命中就直接交给 `findGo()`；只有「一个都没命中」这条分支才自己 `render()`
（把上一次的高亮和淡出清掉）。**每次搜索从 2 次全量渲染降到 1 次。**

#### 3. 渲染主干的两处零行为变更优化

- **节点挂载改 `DocumentFragment`**：一次建好、一次插入。旧写法逐个 `appendChild`，
  等于把「插入」重复 N 遍、每插一次让样式失效一遍。
- **「读测量」与「打截断角标」拆成两趟**：旧循环是「读 `offsetHeight` → 可能 `classList.add` →
  下一个节点再读」，读写交替会让浏览器在每次 `add` 之后重新计算样式；拆开后读的那趟只读、
  写的那趟只写。

#### 4. 拖拽 / 框选期间只动变换（补测试锁住）

平移、缩放、框选本来就已经只改 `transform` 和选框、不碰渲染主干 —— 本轮补了断言
（**平移 10 帧期间 `render()` 调用次数必须为 0**），防止以后有人在 `mousemove` 里加回一次 `render()`。

#### 5. 折叠子树不进布局 + 渲染耗时自查

- 折叠（或被「显示到第 N 层」挡住）的子树**根本不参与定位计算**：`render()` 的遍历与
  `layout()` 都以 `collapsed || isCut` 为界。本轮补了断言：**两次渲染之间，被折叠子树里的
  `x / y` 一个像素都不动**。
- 每次渲染的真实耗时记进 `renderCost`、次数记进 `renderCount`，在 📊 统计面板新增的
  **「渲染」**小节里显示（上次渲染 X ms / 累计渲染 N 次 / 当前显示 M 个节点）。
- 面板还会在「**节点总数 ≥ 400 且上次渲染 ≥ 60ms**」时补一句**可操作建议**：
  折叠暂时不看的整支、或用「显示到第 N 层」把深度卡住。两个阈值收在
  `BIG_GRAPH_NODES` / `SLOW_RENDER_MS` 两处常量，改口径只改一处。
- 顺带：耗时达到 60ms 标红、24ms 标橙，让「卡不卡」从感觉变成能自查的数字。

#### 4. N1 OPML 大纲导入导出 —— 打通「跟别的思维导图工具互换」

这是本轮唯一的**纯新增格式**。之前跟幕布 / Workflowy / 飞书 等大纲类工具互换只能绕道截图或 Word。

- **导出**：`<opml version="2.0">` + `<head><title>/<dateCreated>` + 递归 `<outline text="…" _note="…">`；叶子自闭合；按层级缩进；写进导出面板的「数据与互通」组，占第 9 个数字快捷键位。

- **两个关键细节**：
  - XML 属性值里的**换行必须编码成 `&#10;`**（制表符 `&#9;`），否则多行备注会被 XML 的空白折叠悄悄吃掉 —— 导出去看着正常、导回来只剩一行。

- 「全词」按词边界判定（前后不能再接字母 / 数字 / 下划线），所以搜 `apple` 不会命中 `pineapple`。
- **正则模式下「全词」自动置灰**（正则里直接写 `\b` 即可），不给用户一个按了没反应的按钮。
