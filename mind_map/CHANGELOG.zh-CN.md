## v40 · 2026-10-25（工具国际化：中文 / English 双语界面，一键切换）

**命名定稿**：产品**中文名「思维导图工具」、英文名「MindMap」**；**文件名仍为 `mind_map.html`**。

**核心改造 —— 工具本身支持中英双语，点按钮切换**，国内用户默认中文、国际用户切 English：

- 顶栏最右新增 `EN` / `中文` 按钮。按钮上写的是「**点一下会变成什么**」（Gmail / GitHub 约定），不是当前语言
- 会跟着翻的：顶栏与全部下拉选项、右键菜单（33 项）、14 个面板的标题 / 说明 / 按钮、全部提示条（含撤销步骤名）、
  快捷键速查表 31 条说明、模板卡片与骨架预览、空画布引导、导入预览摘要、导出面板、自动备份面板、工作区、历史版本、步骤面板
- **一个都不翻**：画布上的节点文字、节点备注、节点链接、你自己起的导图名 / 文件名、粘贴进来的原文。
  做法是给 `#nodes` / `#ol-body` / `#tpl-grid` / `#paste` 等容器划了跳过名单，只翻界面、不碰用户内容
- **切回中文是逐字还原**：首次翻译时把原文留在节点上（`__zh` / `__zhAttr`），回切直接放回去，不做反向查表 ——
  否则「标准」这种既是字号又是宽度的词、出现在四个面板里的「清除」，往返一次就会串
- **整段 HTML 单独一张表**：句子里夹 `<b>` / `<br>` / `<code>` 的 9 处，按文本节点拆开翻会断句、英文语序接不上，
  改用 `data-i18n-html` 整段替换（首译存 `__zhHtml`）
- **英文单复数**：词条值写 `单数||复数`，按「数量那个变量」是不是 1 取段（`已删除 1 个子节点` → `Deleted 1 child node`）
- **语言是偏好不是数据**：进 `savePrefs()` 的 `lang`，不进 `serialize()`、不压撤销栈；`normalizePrefs` 用
  `/^(zh|en)$/` 兜底为 `zh`；刷新后语言保持
- **处女画布跟着语言走**：全新用户还没动过手（撤销栈为空 + 只有一个节点 + 没备注/链接/标记）时，中心主题
  `中心主题` ↔ `Central topic`；一旦动过手就当用户内容，一个字都不改
- **导出也跟着语言**：Markdown / Word / Excel / PPT / 独立网页里的表头（`层级 / 编号 / 节点 / …`）、
  「备注：」「已完成 N / M」、文件名后缀、OPML / XMind 兜底名，英文界面下用英文

**词表工程**：905 条 EN + 9 条整段 HTML。手写状态机词法器（注释 / 单双引号 / 模板串含 `${}` 嵌套 / 正则字面量）
从 9112 行里抽出 926 处、去重 814 条，再按区块分成 21 个 JSON 分片，由 `_i18n_build.py` 合并、查重、
查「值等于 key」后注入 `/*<<EN>>*/` 标记位。**不用正则扫源码** —— 文件里有 `/^[a-z]:[\\/]/i` 这类字符类带引号的正则，
正则式扫描会把后面整段吞成字符串（第一版就抽出 38 条假的）。

**顺手修的四个真问题**（前两个是 i18n 自身的，后两个是「拍英文配图时才露出来」的既有缺陷）：
1. 跳过名单把 `textarea` 整块排除，连带它的 `placeholder` 也没翻 → 改成「跳过子树，但仍翻元素自身的属性」
2. 快捷键面板靠 `data-built` 只构建一次，换语言后不重画 → `applyLang` 里先清标记再重画
3. **导出面板的格式名和说明挤在同一行**：`.fmt .tt` / `.dd` 都是行内 `span`，中文靠字形还能分辨，
   英文直接读成 `Image .pngHigh-resolution bitmap…` → 两者改成 `display:block`，各占一行
4. **短标签被误判成「文字被截断」**：`.txt` 会按内容收缩，`QA` 这种两个字母的节点只有 20px 宽，

   （英文界面里 `QA` / `R&D` / `KPI` 很常见）→ `txtClipped()` 加一道「单行且无横向溢出直接返回 false」

**验证**：新增 jsdom 套件 `i18n.js` **71 条**（词表完整性 / `tr`-`trf` 语义 / 逐面板扫残留中文 / 用户内容不翻 /

`elementFromPoint` 真实命中 / 模板卡与速查表不重叠 / 连切三轮布局无残留 / 浮层仍是 14 张 /
导出卡「说明排在格式名下面」/ 短标签不误判截断 + 长文本仍盖角标）。另新增 2 份反证

## v38 · 2026-10-25（第 40 轮 · 真机三问题「上一轮没修好」的根因修复）

用户复测后指出 v37 那三条"依然存在"。逐条查根因，结论是**上一轮改的位置不对**，不是修法不彻底：

1. **☰ 抽屉底部按钮看不到、也滑不动** —— 真根因是**层叠上下文倒挂**，`flex-shrink` 只是次要因素。
   `#navdrawer` 是 `<header>`（`z-index:20`）的子元素，它自己的 `z-index:90` 只在 header 这一层层叠上下文里有效，
   实际绘制封顶在 20；而 `#navscrim` 是 `<body>` 直接子元素、`z-index:85` —— **遮罩骑在整个 header 上面，
   把抽屉连人带滚动一起罩住**。手指落下去命中的是遮罩，抽屉既收不到滚动、视觉上也被压暗，看着就是"按钮少了"。
   - 修法：遮罩 `z-index` 85 → **19**（高于画布、低于 header）；抽屉高度改 `100dvh`（`bottom:0` 落在布局视口底部，
     最后一行正好躲在地址栏后面）；`body.mnav` 时把 FAB（57 层）一并收起，免得浮在抽屉上被误点。
   - 证据：真 Chrome `elementFromPoint(抽屉中部)` 修复前返回 `navscrim`、修复后返回 `btn-undo`。
2. **长按仍弹系统「复制/搜索/全选/翻译」条** —— v37 把禁选写在 `body.touch` + `@media(max-width:760px)` 里，
   而部分安卓内核不报 `pointer:coarse`、横屏宽度又超过 760px，两个断点都不命中 → 整段失效。
   - 修法：禁选提到**基础样式、无条件生效**，覆盖 `#stage` 与**全部子孙**（角标 / `.txt`），
     同时带 `-webkit-user-select`（iOS / 旧安卓只认前缀）与 `-webkit-touch-callout:none`（iOS 长按气泡归它管）；
     `#stage textarea` 单独放开。再加一层 `selectstart` 拦截：**没有选区，系统就没东西可弹**。
3. **右键菜单底部「删除所有子节点 / 删除该节点」出屏** —— `calc(100vh - 16px)` 把地址栏那段也算进去了，
   且 `showCtx` 里 `h` 可能大于 `innerHeight`，`Math.max(8, innerHeight-h-8)` 退化成 `top=8`，底部照样溢出。
   - 修法：`#ctx` 改 `calc(100dvh - 16px)`；`showCtx` 先按 `window.innerHeight - 16` 写死 `maxHeight` 再量高；
     手机上隐藏 `<kbd>`（没有物理键盘，纯占位还撑宽撑高）并压紧行距，一屏放得下。
4. **（新需求）空白画布时手机端不要「画布还是空的 / 按 Tab 加子节点」** —— 那句话是 `#empty-tip`（O7），
   不是 `.hint`（v37 隐藏错了对象）。窄屏 `#empty-tip{display:none !important}`，只留中心主题节点。

验收：jsdom `mobile.js` 60/0（43 → 60）、反证 **21 轮全红 + sha1 OK**（11 → 21，另加 1 轮真 Chrome 层级反证）、
全量回归 37 套 **2779/0**、真 Chrome **55/0**（37 → 55）。

## v37 · 2026-10-26（第 39 轮 · 手机端三个真机问题修复 + FAB 常用操作面板）

用户真机反馈三条，逐条修：

1. **☰ 抽屉最下面的按钮看不到、也滚不到** —— 根因是抽屉虽是 `overflow-y:auto`，但它是 `flex-direction:column`，
   里面的 `.btn-group` / `.divider` 默认 `flex-shrink:1`，会被压缩到容器高度，内容被裁掉且永远滚不出滚动条。
   修法：抽屉子项加 `flex:0 0 auto`（不压缩），抽屉加 `overscroll-behavior:contain` + 底部安全区 padding。
2. **长按节点弹系统「复制/搜索/全选/翻译」条，与我们的菜单互相干扰** —— 原生选择条是「文字被选中」触发的，
   与 `contextmenu` 是两套机制（只挡 `contextmenu` 挡不住它）。修法：`body.touch` 下 `#stage` / `.node` 统一
   `user-select:none` + `-webkit-touch-callout:none`（编辑框 `textarea` 仍可选中）；`showCtx()` 与画布
   `contextmenu` 里顺手 `getSelection().removeAllRanges()`，把已经拉起来的选区清掉。
3. **功能页（右键菜单）显示不全，最底下的「删子节点 / 删节点」看不到** —— 菜单条目比屏幕还高，
   但 `#ctx` 没有高度上限。修法：`#ctx` 加 `max-height:calc(100vh - 16px)` + `overflow-y:auto`，
   内容超高时菜单内部自己滚，底部条目可达。
4. **把最常用操作并到右下角 + 号** —— FAB 点一下展开「常用操作」面板（子节点 / 同级 / 编辑 / 删子节点 / 删节点），
   点任一项执行并自动收起；点遮罩 / 按 `Esc` 收起；按当前选中态自动置灰（无选中禁用同级/编辑/删节点，
   root 禁用删节点，无子节点禁用删子节点）。面板只在窄屏出现，桌面端外观与行为不变。

专项 `mobile.js` 28→**43 条**、反证 `_falsifyMobile.py` 10→**11 轮全红（0 假绿）+ sha1 还原 OK**、
真 Chrome `_chrome_mobile.py` 26→**37 条全绿**（新增：抽屉压到 320px 后真滚到底、最末按钮进可视区、
触屏下 `user-select:none`、右键菜单 `overflow-y:auto` / `max-height` 生效）、全量回归 **37 套 2762 条 0 失败**。
文件 8965 → **9054 行 / 500259 字节（约 489 KB）**。

## v36 · 2026-10-26（第 38 轮 · 移动端自适应导航骨架）

按「建议起步组合」开工：**顶栏只留 ☰+标题（其余进抽屉）+ 左侧滑入抽屉 + 右下 FAB「＋」**。

- **诊断结论**：画布本身已触屏就绪（C1 的 `touch-action:none` + `pointer:coarse` 命中区放大），
  「手机打不开」的根因是**外壳未做窄屏折叠**——顶部约 40 个控件（含 9 个 `<select>`）在 ≤760px 折成巨高 header，
  `syncHeader()` 把实测高度写进 `stage.top` 把画布压没；且无汉堡抽屉、`#outline` 300px 固定推画布、弹窗/浮动件无收口。
- **做法**：桌面用 `display:contents` 让 `<nav>` 融入顶栏（行为不变）；窄屏用 `position:fixed` 抽屉
  （**绝不撑高 header**，否则退回"画布消失"现状）。FAB 调 `addChild(selected || root)` 解决手机无物理键盘问题。

`- ↓`、`1. ↓`、`# ↓` 这种带列表 / 编号 / 标题标记的，剥掉标记后同样算。

**不收**：`|`（表格）、`v` / `V`（字母）、`---`（分隔线）、行内的 `温度 ↓` 与 `A → B`（那是节点名字，不是分隔符）。

## v34 · 2026-10-19

第十二轮「**N3 节点链接 · URL / 本机路径**」。

资料整理、学习笔记、项目清单里，一个节点常常要指向一份外部材料 —— 一个网页、一份本地 PDF、
一个共享目录。以前只能把地址写进节点名字（又长又丑）或备注（看不见），现在有了专门的 `link` 字段。

### 三件事必须同一套函数判出来

`linkNorm` / `linkKind` / `linkHref` 三个函数是唯一入口，否则会出现「能挂不能开 / 能开不能导出 /
导出的是坏链接」各漏一边：

| 你挂的是 | 点一下 | 导出成 |
| --- | --- | --- |
| `https://…` / `http://…` / 邮件 / 电话 | **新标签页打开** | 真链接（MD / HTML / Word 的 `w:hyperlink`） |
| `D:\资料\x.pdf` / `/Users/a/b.md` / 相对路径 | **复制到剪贴板** | 文本附注（`> 链接：…` / Word 灰字行 / Excel 一列） |
| `javascript:` / `data:` / `file:` 等 | **拒绝并说明原因** | **哪儿都不出现** |

浏览器**不允许**网页直接跳 `file://` 或本地路径 —— 硬跳只会静默失败。所以本机路径走「复制 + 说清原因」，
而不是假装成功。危险协议（能执行脚本的那些）一律不认：导出的独立 HTML 是要发给别人双击打开的，
一个 `javascript:` 链接就是现成的 XSS。

> 判定顺序里藏着一个坑：**盘符必须先于协议判**。否则 `D:\资料\x.pdf` 会被当成一种叫 `D:` 的协议，
> 直接落到「不认」那一档 —— 而本机路径恰恰是这个功能一半的用途（反证里把它改回去，10 条断言当场变红）。
> 同理，协议名刻意**不许带点**，否则 `a.com:8080` 这种「域名 + 端口」也会被误判成协议。

### 冲突：Ctrl+单击仍然是加选

报告里点名的冲突就在这里。B6 的 `Ctrl/⌘+单击` 是「加选 / 减选」，**绝不能抢**。
所以打开链接走两条别的路：

- **点节点右上角那颗链环**（它是唯一可点的角标，其余几颗都是纯展示）；
- **`Alt+单击` 节点**（鼠标 Alt 键在本工具里原本没有别的用途）。

没挂链接的 `Alt+单击` 会**退化成普通单击**，不会变成「点了没反应」。
反证里把 `Alt` 换成 `Ctrl`，4 条断言立刻变红。

键盘入口：`Ctrl+Shift+L` 挂链接（与备注的 `Ctrl+Shift+M` 对称），`Alt+Enter` 打开。

### 角标位置：右上角，与备注角标错开

四个角早就各占一位（左上语义图标 / 右上备注 / 左下截断 / 右下完成），所以链接跟备注**挤在同一个角**，

且加了角标之后节点宽度一个像素都没变（角标是纯绝对定位，不参与 tidy-tree 的度量）。

### 导出：12 种，各带一份

| 格式 | 链接怎么出现 |
| --- | --- |
| JSON | `link` 字段（只在非空时写，老数据形状不变） |
| Markdown / 复制为 Markdown | `[节点文字](url)`；地址含空格 / 括号时写成 `<url>`；本机路径走 `> 链接：` 附注 |
| 独立 HTML | 嵌的是 `serialize(root)`，自动继承 |
| Word | `w:hyperlink` + `word/_rels/document.xml.rels` 里的 External 关系，**同一个地址只登记一条** |
| Excel | 多一列「链接」 |
| PPT · 分页大纲 | 节点下方一行蓝色小字（刻意不用 `<a:hlink>`：rId 要在两个函数之间来回对，为了「能点」冒这个险不划算） |

**回读侧**：Markdown 的 `[文字](url)`（含 `<url>` 写法）、`> 链接：` 附注行、OPML 的 `_link`、XMind 的 `href` 都能认回来。

| 区域 | 内容 |
| --- | --- |

| 中间一行（高亮 `.cur`，不可点） | **现在的内容** + 节点数 |
| 下面一段 | **可撤销**：从「刚发生的那一步」往下排到最早的一步 |

2. **先验后动**：先把要经过的每一步的快照都解析一遍，有一条读不出来就**整次拒掉**并说明，

第十轮「**C5 工作区打包 · 24 个页签整包搬迁**」。

页签其实一直都在：每个浏览器标签页在 `localStorage` 里各占一个槽（`SLOT_MAX = 24`），
关掉页面内容也不丢。问题是**没有任何入口能看见它们** —— 用户既不知道那 20 多张图还在，
也没法把「这台机器上的 8 张图」一次搬到另一台电脑上（只能一张张导出、再一张张打开另存）。

这一轮补的是「入口 + 搬运」，没动存档机制本身。

### 新增「🗂 工作区」面板

| 能做什么 | 行为 |
| --- | --- |
| 看见 | 每行显示名字（没起名字就用根节点文字）、节点数、多久以前动过；当前页标 **本页签**，开在别的标签页里的标 **其它页面开着**；内容坏掉的槽也照样列出来（否则永远删不掉它） |
| 切过去 | 「打开」→ 当前这页先落盘，再整页换成那一页 |
| 单独另存 | 「另存」→ 存成 `.json`，文件名就是清单里显示的那个名字 |
| 删掉 | 「删」→ 变成「确定删」→ 再点一次才真删；历史快照一并清掉 |
| 整包搬走 | 「导出工作区包…」→ 一个 `工作区-N个页签-YYYYMMDD-HHMM.json` 装下全部页签 |
| 整包搬回来 | 「导入工作区包…」；直接拖进画布 / 用顶部「打开」也认这个包 |

### 导入的三条硬边界（每条都有反证守着）

1. **只新增，不覆盖**：每个页签都拿新 id，同一个包导两次就是两份。
2. **绝不挤掉老页签**：满了 24 个就**明确拒绝**，不依赖 `pruneSlots` 去腾地方 ——
   那个函数按「最久没动」删，会连用户还没导出的图一起删掉。
3. **旧时间戳不带进来**：导入的槽 `at` 一律取「现在」。包是十天前打的就照抄，
   `pruneSlots` 一跑会把这批刚导进来的页签当过期清掉。

> 导入的槽标成 `closed: true`：它不是「另一个正在开着的页面」，所以**能立刻打开**；
> 而真正被别的页签占着的槽，「打开」和「删」都是禁用的（两个页面写一份存档必然互相覆盖）。

### 切换页签要做的三件事

按顺序：`saveNow()`（把现在这页写进去）→ `releaseSlot()`（旧槽标「已关闭」，别人能接手）→
换 `slotId` / `sessionStorage` → 重建画布。其中两件是踩过才知道必须做的：

- **撤销栈必须清空**。不清的话，切到 B 页签后按 `Ctrl+Z` 撤回的是 A 页签的状态，
  再一保存就把 A 的内容写进 B 了。`redoStack` 与多选集同理。
- **离开前必须真落盘**。`save()` 是 250ms 防抖，直接切会把这 250ms 里的改动留在空气里。

### 顺带做的两处收口

- 把 `save()` 的函数体抽成 **`saveNow()`**（`save()` = 防抖 250ms 调它）。
  工作区清单、打包导出、切页签三处都要「现在这一份」，否则会报旧名字、导出的包里少一句。
  写不进去的那套处理（配额识别 / 自救 / 重试）仍然只有一份。
- `readFile` 里 **先认 `kind: 'workspace'` 再认 `text`**：工作区包也是 `.json`，
  不先认的话会被当成单张导图，把当前画布整个替换掉。拖文件的确认框文案也跟着改成
  「单张导图会替换 / 工作区包会合入、不动画布」。

### 反证抓到的四处「断言没牙齿」

第一轮 29 次反证里，有 4 条改坏之后**照样全绿** —— 全是测试自己的漏洞：

1. **「打包前不落盘」测不出来**：前一段刚调过 `openWs()`，它顺手把内容落盘了。
   → 补一个「只调 `wsExport`、不先开面板」的场景才变红。
2. **「不校验 kind」测不出来**：单张导图没有 `slots` 数组，紧跟着的那条检查会兜住。
   → 改成「整段校验一起拆掉」的配对替换，并补一条「要明确告诉用户单张导图该用『打开』」。
3. **「不清多选集」测不出来**：切换前根本没选中任何节点，两边都是空集。
   → 切换前先真选中一个节点。
4. **「删别人的活槽不拦」测不出来**：删除是两步确认，只点一次时槽当然还在。
   → 连点两次再断言。

## v31 · 2026-10-18

第九轮「**C3 多布局 · 组织结构图**」。以前只有「左→右」一种方向 —— 汇报关系（谁向谁汇报）用
竖着读才顺，可这工具画出来永远是横的，只能截图后自己脑补。

这一轮加了 **布局** 下拉：**左右**（思维导图，默认）/ **上下**（组织结构图）。

### 动手前先定映射表

| 关注点 | 原来（左→右） | 现在（上→下） | 落点 |
| --- | --- | --- | --- |
| 层间方向 | x = `colX[depth]` | y = 按层累计行高 | `layoutOrg()` |
| 同层排布 | y = tidy 子树 | x = 按子树横向跨度铺开 | `layoutOrg()` |
| 节点定位 | `left = x` / `top = y - h/2` | **不变** | `render()` 一行没动 |
| 连线端点 | 父右中 → 子左中 | 父下中 → 子上中 | `edgeGeom()` 单点 |
| 折叠圆点 | 节点右侧中点 | 节点底部中点 | CSS `body.layout-org` |
| 方向键 | ← 父 / → 子 / ↑↓ 同层 | ↑ 父 / ↓ 子 / ←→ 同层 | 键盘处理单点 |
| 边界 / 适应窗口 / 缩略图 / 框选 | 用 x/y | **不变**（org 的 x 天然从 0 起） | 一行没动 |

关键取舍：**两套布局共用同一份坐标语义（x = 左沿，y = 垂直中心）**。
这样 `render()` 的定位、`bounds()`、`fitWidth()`、`ensureVisible()`、缩略图、框选命中
全都不用改 —— 只改「x/y 怎么算」和「连线从哪条边出去」这两件事。
否则每多一个消费方就要多一处 `if(纵向)`，日后必然漏一处。

### 纵向布局算法

- **行高按这一层最高的节点取**（`orgRowY()`），同层节点才会对齐成一条线；
  节点各自居中会画成波浪线。
- **先量子树跨度、再摆放**（`orgMeasure()` → `place()`）：子节点从左到右按跨度铺开，
  父节点居中在「首尾子节点的中点」上 —— 不是整块跨度的中点，否则一枝独苗也会歪。
- **折叠 / 「显示到第 N 层」挡住的子树一律不参与测量与摆放**，两处都要判（`orgMeasure` + `place`），
  漏一处图就会被看不见的东西撑开。
- 坐标自然满足 `minX = 0 / minY = 0`，所以下游那些「默认左边界是 0」的代码不用动。

### 四种输出共用一份端点函数

原来屏幕、PNG、SVG 导出、PPTX 导出**各写了一遍**「父右中 → 子左中」的贝塞尔：
加一种布局就要改四处，漏一处就是「屏幕上对、导出的图错」。
现在统一成 `edgeGeom(p, c)`，返回两个端点 + 两个控制点，四家都调它。

> 顺带发现 PNG 传给子节点的数据只有 `{x, y}`，纵向端点要用到 `h`，一并补上。

### 顺手删掉的冗余

`sameDepthRow()` 本来想按布局写两种排序，写完发现不用：横向布局同层 y 各不相同（按 y 排），
纵向布局同层 y 完全相等、会自动落到 x 这一级 —— 一条比较链两种布局都成立。
分支删掉，注释留下原因。

### 反证抓到的两处「断言没牙齿」

1. **「折叠后父节点自己也要重新居中」原来没测**：只验了「后面的兄弟左移」，可 `place()` 里
   漏判 `collapsed` 时兄弟的 x 完全不受影响 —— 加了一条「折叠后的父节点 x 回到 0」才变红。
2. **「下拉少一个选项」会直接把测试跑崩**（`options[1].value` 空指针），崩溃虽然也算抓到，
   但看不到是哪条断言在起作用 —— 补上长度守卫，改成干净的失败。

### 真 Chrome 复核抓到的三处探针错误（不是产品 bug）

- 量根节点的圆点却拿一级节点的右沿去比 —— 量错了对象；
- 拿「顶边相同」验同层对齐 —— 真浏览器里节点高度不一样（长文本 73px vs 46px），
  正确口径是**中心线相同**（jsdom 里高度都是桩 56，所以永远看不出来）；
- 忘了关「欢迎浮层」，`anyPanelOpen()` 一路挡住键盘导航，四条方向键断言全是假的「通过」。

## v30 · 2026-10-18

第八轮「**C1 触屏 / 平板**」。以前这套工具在平板上几乎是废的：`pointer*` / `touch*` 监听数量是 **0**，
全靠 13 处 `mousedown`，手指只能点一下选中，拖不动、缩不了、更叫不出右键菜单。

这一轮把它补成「手指也能干完所有事」，同时**一行都没改鼠标的行为**。

### 两条动手前定的红线

1. **鼠标路径不迁移，只加早退**。`PointerEvent` 会**先于** `mousedown` 触发，两套监听都处理就是
   「按一下动两下」。所以 `pointerdown` 里遇到 `pointerType === 'mouse'` 一律 `return`，
   鼠标继续走原来的 `mousedown / mousemove / mouseup`。
   > 为什么不干脆全迁到 pointer 事件？30 套既有测试全部用 `mousedown` 派发，迁过去等于把
   > 1900 多条断言的语义重写一遍，风险远大于收益。
2. **两套输入共用同一份实现**。把原来 stage 上那三个匿名处理器抽成 `stageDown / stageMove / stageUp`，
   鼠标与手指都调它 —— 否则「鼠标能拖、手指不能」的偏差迟早冒出来。`stageMove` 多一个阈值参数
   （鼠标 3px、手指 10px），因为手指抖动本来就比鼠标大。

### 手势清单

| 手势 | 做法 |
| --- | --- |
| 单指平移 | 与鼠标同一套 `tx/ty`；新的一下按下先把上一轮残留的 `moved` 清掉 |
| 双指缩放 | 记住两指中点底下的**世界坐标**，`tx = (mid.x - r.left) - wx * ns`；松开一根时用剩余那根重新对基准并把平移接回来 |
| 长按出菜单 | 520ms；移动超过阈值或抬手都取消；触发时先 `cancelNodeDrag()`，之后挡掉安卓补发的原生 `contextmenu` |
| 双击改名 | 间隔 < 340ms + 落点 < 30px + 同一个节点；拖动过的节点不算「点击」 |
| 拖节点改挂 | 阈值 10px（鼠标 5px），命中检测仍用 `elementFromPoint` |
| 缩略图挪视口 | 缩略图上单独接 pointer 三件套（它挂在 `body` 上，不在画布手势层里） |
| `pointercancel` | 缩放态 / 拖拽态 / ghost / `body.dragging-node` / 指针表全部收干净 |

### CSS

- `#stage{touch-action:none}`：**不写这一条，浏览器会把手指拖动当页面滚动，中途发 `pointercancel` 掐断手势** —— 这是整个改造的前提。
- `#stage{top:var(--head-h,56px)}`：窄屏工具栏会折行，真实高度仍由 `syncHeader()` 写 `style.top`。
- `@media (pointer:coarse)`：折叠圆点 20px → 26px（中心继续压在节点右边缘）、大纲勾选框与浮层 ✕ 加大、
  画布禁选中文字**但编辑框例外**（否则改字时放不下光标）。
- `@media(max-width:760px)`：工具栏收窄；只收 `header .spacer`，不误伤查找栏的布局 spacer。

### 真机复核抓到的两个 bug

1. **`moved` 串台**：`moved` 只在 `stageDown`（按在空白处）里清，按在节点上时不清 →
   「先拖过画布、之后**双击节点永远进不了编辑**」。修法：`pointerdown` 的单击分支统一 `moved = false`。
   > jsdom 里每个小节都调 `reset()` 把 `moved` 归零，所以这条**只可能被真浏览器抓到**。
2. **探针派发位置错了**：把 `pointerdown` 派发到 `#stage` 上等于「点在空白」，长按 / 拖拽 / 双击全都不成立，
   一次挂了 11 条。真手指是落在**节点元素**上的 —— 改成 `peOn(nodeEl, ...)` 后全绿。

### 反证顺手删掉了两处死代码

- `stageUp(e, keepSel)` 的 `keepSel` 参数**从来没起作用**：按在节点上时 `dragging` 永远是 false，
  「取消选中」那条分支根本走不到。删掉参数，换成 `inNode` 的反证。
- `armLongPress` 里的 `selectNode(n)` 是**冗余**的：`pointerdown` 已经选过了。删掉。

> 能删掉代码的反证，比能加测试的反证更有价值 —— 它证明的不是「测到了」，而是「本来就多余」。

### 踩坑：反证脚本的备份必须是「原件」

上一轮结束时产品文件里还留着一处 `/* FALSIFY */`（`serialize()` 里写 `done` 的那一行被替换后没还原），
而反证脚本的备份机制是「跑之前把当前文件复制一份」—— 于是残留被当成了原件，在这一次的
「终局校验」里被 `n2.js` 5 条失败当场戳破。现在 `_falsifyC1.py` 结尾用 **sha1 核对还原结果**，

### 核心决定

- **只存 `done`，进度不存**。`done` 只在 `true` 时落盘（和 `note` / `mark` / `color` 一个口径），
  所以老数据读进来、存回去、导出去，形状与 v28 完全一致（有断言守着）。
- **进度是派生的**：`doneStat(n)` 按「自己的全部下级」现算（口径与 `totalNodes` 一致，不含自己）。
  存的进度会撒谎——勾了某个子节点，父节点存的那个百分比不会自己变，除非每次改动都向上逐级重算，
  漏一处就永久错。现算永远和事实一致，也省掉一次数据迁移。
- **角标不参与排版**：对勾是追加的绝对定位元素，删除线不改文字度量 → 真 Chrome 逐节点比对确认
  加完成态后每个节点的 `offsetWidth / offsetHeight / left / top` 与 tidy-tree 的 `x / y / w / h`
  **一个像素都没变**。
- **四个角已经各占一位**（左上语义图标 / 右上备注编号 / 左下截断提示 / 右下「+N」），
  对勾放**右下角**，完成时把「+N」往左让开 26px。有静态守卫按四条 CSS 规则逐一对角，防止以后撞位。

| 字段 | 含义 |
| --- | --- |
| `note` | 这个键跟**浏览器默认行为**的关系，给用户一句实话（如「浏览器默认拿它开审查元素」） |

#### O5-1. 冲突审查（报告点名的两个，加全表扫一遍）

报告要求重点审 `Ctrl+Shift+C`（Chrome DevTools「审查元素」）和 `Ctrl+D`（浏览器「添加书签」）。
两个都保留原键（都在 keydown 里 `preventDefault()` 拦下），但结论不同：

- **`Ctrl+D`**：Chrome / Edge 允许页面拦下，同类应用（如 Google Sheets 的向下填充）也是这么做的 → **不冲突**，只在说明里写清它跟书签的关系。
- **`Ctrl+Shift+C`**：多数现代浏览器能拦下，但**部分版本会优先响应 DevTools** → 潜在冲突，**补一个不跟浏览器抢的备用键 `Ctrl+Alt+C`**。
- **`F1`**：部分浏览器会先打开自己的帮助页 → 潜在冲突，备用键就是 `?`（`act` 与 `?` 相同，属「同一动作的复用」）。

顺带把整张表扫了一遍：`Ctrl+F` / `Ctrl+Z` / `Ctrl+Y` / `空格` / 方向键都是「浏览器有同名默认行为、

#### O6-1. 浮层语义：10 张卡一次补齐

`role="dialog" aria-modal="true" aria-labelledby=<标题 id>` —— 统计 / 备注 / 批量 / 模板库 / 欢迎页 /
导入 / 导出 / 自动备份 / 速查九张用 `dialog`，**确认框用 `alertdialog`**（它要打断用户）。
标题都套了一层带 id 的 `<span>`，`aria-labelledby` 指过去；每张卡里的 **✕ 补上 `role="button"` + `tabindex="0"` + 独立 `aria-label`**。

另外两处：`#ctx` 右键菜单补 `role="menu"`，15 行补 `role="menuitem"`；欢迎页四张大卡片
（原本是纯 `div`，键盘完全够不着）补成 `role="button" tabindex="0"`。

`role=button` 的 `<span>/<div>` 不会自己响应回车和空格，所以加了一条统一委托：
命中就把事件 `preventDefault()` + **`stopPropagation()`** + `click()`。
**`stopPropagation` 是必须的** —— 不然点面板里的 ✕ 时，那个空格会一路冒泡到 window，
撞上画布那套「空格＝折叠展开」，一次按键干两件事（真 Chrome 里验证过）。

#### O6-2. 焦点管理：进得去，出得来，跑不掉

三个动作，全文件只做一遍、所有浮层共用：

1. **进得去**：打开时记下「是谁打开的」，把焦点送进卡片里**最合适的那个控件**。
   选择顺序是「正文里第一个控件（**跳过复选框 / 单选框**）→ 页脚第一个 → 卡片本身」：
   导出面板一进来停在第一个格式按钮而不是「仅导出选中分支」（不然随手一个空格就把范围改了）；
   确认框用 `prefer` 指定停在**「取消」**上（别让误回车把画布清了）。
2. **出得来**：关闭时把焦点**还给那个触发按钮**，不是还给 `body` —— 否则键盘用户会被甩回页面开头，
   接着按 Tab 得从头一个个摸过去。触发者若已不在文档里就安静地不还。
3. **跑不掉**：`Tab` / `Shift+Tab` 在卡片内部循环，不会跑到背后那块被遮住的工具栏上。
   这条放在全局 keydown 的**最前面**（模态的定义性行为，不能被后面任何一条 `return` 抢在前面）。

顺带修掉一个**真实缺口**：老的 `Esc` 链只认了模板库 / 备注 / 批量三个，
**统计、导入、欢迎页、确认框、自动备份按 Esc 是没反应的** —— 一个标了 `aria-modal` 的对话框居然关不掉。
现在统一成「点它自己的 ✕」，走各面板既有的关闭逻辑，焦点归还也就一并带上了。

#### O6-3. 大纲补 tree 语义 + roving tabindex

`#ol-body` 补 `role="tree"`；每一行补 `role="treeitem"` / `aria-level`（与画布同一口径：depth + 1）/
`aria-expanded`（有子节点才写）/ `aria-selected`。

再补上 **roving tabindex**：整棵大纲只留**一个** Tab 站（当前选中那一行，其余 `tabIndex = -1`）——
不这么做的话，几十个节点会把 Tab 键排成一长串，键盘用户得按上百次才能走到别处。
配套的键盘操作：**↑↓ 走行、←/→ 折叠展开、Enter 定位、F2 就地改名**。
方向键在行间走，所以必须 `stopPropagation()`，否则会冒泡到 window 的画布导航，**按一下动两处**。
`←/→` 展开后 `render()` 会重建整棵大纲，新行是新元素，**焦点得自己按 `__olNode` 接回来**，否则焦点就掉了。

#### O6-4. 缩略图：给 canvas 一条键盘替代路径

`<canvas>` 里的图形屏幕阅读器读不出来，鼠标拖拽键盘也够不着。补 `tabindex="0"` + `role="img"` +
描述键盘用法的 `aria-label`，并接上键盘操作：**Home / End 直接跳到第一个 / 最后一个一级分支，
←/→ 在分支之间逐个走**，跳过去的同时选中并把它带进视野（视口 `transform` 真的会变）。

#### O6-5. 顺手抓到一个既有 bug：重复的 id

`bk-close` 这个名字被用了两次 —— 批量文本工具的 ✕ 和自动备份面板的「关闭」按钮。
`getElementById` 只认第一个，于是两处 `onclick` 赋值**全落在批量面板那颗 ✕ 上**：

### 第 28 轮（大图）：O3 渲染节流与可感知性能

#### 0. 先说边界：`render()` 没有变成异步

`render()` 在全文件有 **60 多处**调用点，而且绝大多数是「先 render、再立刻读 `flat` / 节点元素」的
同步依赖 —— 导出、`fitWidth()`、缩略图、大纲、`ensureVisible()` 全都靠它。把它包成 rAF 异步，
这些调用点会全部读到上一帧的结果，属于自找麻烦。

所以这一轮做的是**分流**：`render()` 保持同步，另开一条 `renderSoon()` 给「高频输入」走。

#### 1. `renderSoon()`：同一帧里的多次请求合并成一次

- 真正会一秒触发几十次的只有**搜索框边打边搜**（`findInput` 的 `input`）。现在它走 `renderSoon()`：
  同一帧里的第 2、3、N 次请求直接被并掉，一帧最多渲一次。输入框的值在**回调里**读，
  所以拿到的永远是最后一次输入。
- 反过来，**同步 `render()` 一进门就先 `cancelRenderSoon()`** —— 这一帧既然已经有人真的渲了，
  排队里的那次就没有意义，取消掉免得白渲两遍。
- 关掉搜索条时会 `cancelFindInput()` 撤掉排队中的那次；队列回调里还复查一次「搜索条还开着吗」——
  双保险，避免关了搜索条又自己搜回来。
- `rafCall()` / `cafCall()` 把 rAF 的调用方式收在一处（缩略图的 `mmSchedule()` 也改用它）。

#### 2. `findRun()` 少渲一遍

旧写法是 `findCompute(); render(); if(命中) findGo(1);` —— 而 `findGo()` 内部本来就会
`render()` + 定位 + 刷新计数，**前面那次全量渲染的结果立刻被下一次覆盖**，纯属白渲。
现在：有命中就直接交给 `findGo()`；只有「一个都没命中」这条分支才自己 `render()`
（把上一次的高亮和淡出清掉）。**每次搜索从 2 次全量渲染降到 1 次。**

#### 3. 渲染主干的两处零行为变更优化

- **节点挂载改 `DocumentFragment`**：一次建好、一次插入。旧写法逐个 `appendChild`，
  等于把「插入」重复 N 遍、每插一次让样式失效一遍。
- **「读测量」与「打截断角标」拆成两趟**：旧循环是「读 `offsetHeight` → 可能 `classList.add` →
  下一个节点再读」，读写交替会让浏览器在每次 `add` 之后重新计算样式；拆开后读的那趟只读、
  写的那趟只写。

#### 4. 拖拽 / 框选期间只动变换（补测试锁住）

平移、缩放、框选本来就已经只改 `transform` 和选框、不碰渲染主干 —— 本轮补了断言
（**平移 10 帧期间 `render()` 调用次数必须为 0**），防止以后有人在 `mousemove` 里加回一次 `render()`。

#### 5. 折叠子树不进布局 + 渲染耗时自查

- 折叠（或被「显示到第 N 层」挡住）的子树**根本不参与定位计算**：`render()` 的遍历与
  `layout()` 都以 `collapsed || isCut` 为界。本轮补了断言：**两次渲染之间，被折叠子树里的
  `x / y` 一个像素都不动**。
- 每次渲染的真实耗时记进 `renderCost`、次数记进 `renderCount`，在 📊 统计面板新增的
  **「渲染」**小节里显示（上次渲染 X ms / 累计渲染 N 次 / 当前显示 M 个节点）。
- 面板还会在「**节点总数 ≥ 400 且上次渲染 ≥ 60ms**」时补一句**可操作建议**：
  折叠暂时不看的整支、或用「显示到第 N 层」把深度卡住。两个阈值收在
  `BIG_GRAPH_NODES` / `SLOW_RENDER_MS` 两处常量，改口径只改一处。
- 顺带：耗时达到 60ms 标红、24ms 标橙，让「卡不卡」从感觉变成能自查的数字。

#### 4. N1 OPML 大纲导入导出 —— 打通「跟别的思维导图工具互换」

这是本轮唯一的**纯新增格式**。之前跟幕布 / Workflowy / 飞书 等大纲类工具互换只能绕道截图或 Word。

- **导出**：`<opml version="2.0">` + `<head><title>/<dateCreated>` + 递归 `<outline text="…" _note="…">`；叶子自闭合；按层级缩进；写进导出面板的「数据与互通」组，占第 9 个数字快捷键位。

- **两个关键细节**：
  - XML 属性值里的**换行必须编码成 `&#10;`**（制表符 `&#9;`），否则多行备注会被 XML 的空白折叠悄悄吃掉 —— 导出去看着正常、导回来只剩一行。
  - 本工具是**单根模型**，而 OPML 允许多个顶层条目：**一个**就直接当中心主题，**多个**就套一层用 `<title>` 命名的中心主题（多个顶层时的计数按合并后的树算）。
- 文案同步：欢迎页、导入面板、`hint-view`、接受类型（`.json,.xmind,.opml`）、拖拽确认框都说清了 OPML。

#### 5. O2 搜索高级选项（Aa / 全词 / 正则）

- 搜索框右侧三个开关：**区分大小写（Aa）**、**全词匹配**、**正则表达式（`.*`）**。三个都是**开关式**，开启时按钮亮起主题色；点一下立刻用新口径重搜，不用再敲一次关键词。
- 「全词」按词边界判定（前后不能再接字母 / 数字 / 下划线），所以搜 `apple` 不会命中 `pineapple`。
- **正则模式下「全词」自动置灰**（正则里直接写 `\b` 即可），不给用户一个按了没反应的按钮。
- **搜索与替换共用同一套口径**：`findCompile(qIn)` 一处把「关键词 + 三个开关」编译成 `{test, replace}`，替换框里可用 `$1` 引用分组（例如 `^[0-9]+\. *` 换成空，一次清掉所有行首编号）。
